## p8.38 — Section 6 blocks every publish, because a local clone has no reflogs · 2026-11-03 · @Alpha-30-creator

**What changed:** `scripts/check.sh` takes `--no-object-store`, and says so when it is used.
`scripts/publish.sh` passes it for the throwaway clone it assembles, and only there. Argument
parsing became explicit: an unknown flag exits 2 instead of being treated as a mode.

**Why:** `publish.sh` builds its candidate in `git clone --no-hardlinks` of the target and runs
`check.sh` inside that clone. A local clone copies the whole object store but **not the reflogs**,
and `git fsck` treats reflog entries as roots — so every object the source's reflog was holding
arrives in the candidate with nothing reaching it. Measured on the same repo minutes apart:

| | unreachable blobs | trees | commits | undeclared |
|---|---|---|---|---|
| the repo itself | 29 | 42 | 13 | **0** |
| a `--no-hardlinks` clone of it | 46 | 105 | 51 | **1** |

The undeclared blob is a pre-p2.2 skill version carrying the private project abbreviations — real
content, **reachable in `main`'s history** from `10177fb` and fixed in `0af4bba`, so section 6
correctly ignores it in the source, reachable history being explicitly outside its scope. In the
clone nothing reaches it, so it reads as residue. Section 6 was therefore refusing every publish on
the author's reflog rather than on the bytes being published. Fail-safe, and a complete stop: the
library could not reach the public repo at all.

Found by p8.37's own publish — the first to run against a `main` carrying section 6, since p8.31's
publishes ran against the four-section script. The regression shipped on 2026-11-02 and was caught
on 2026-11-03 by the loop using itself.

**Decisions:**
- **Half the fix is the announcement.** The section prints which check it did not run and why, and
  the closing line reads `all checks passed EXCEPT section 6 (object store), which was skipped by
  request`. A publish log can never read as a clean six-section pass. *Rejected:* skipping
  quietly, which is the exact defect class this repo keeps fixing — p8.24, p8.31 and p8.37 are all
  the same shape.
- **A flag, not context detection.** *Rejected:* having section 6 work out whether it is inside a
  candidate clone. A guard that guesses its own context is worse than one that is told, and the
  heuristic would have been "am I in a temp directory", which is both fragile and silent.
- **Only the clone opts out.** The target repo's preflight, its `--staged` run, the pre-commit
  hook and CI all still run six sections. *Rejected:* making section 6 informational like section
  4, which would undo p8.31 entirely.
- **Not baselining the blob.** It is reachable here, and clone artifacts are unbounded — the
  baseline is for measured residue with a decision behind it, not for whatever a clone invents.

**Evidence:** proven by a real publish end to end, which is what the criterion asked for. The
candidate scan printed `all checks passed EXCEPT section 6 (object store), which was skipped by
request`; the staged-tree run and the target's own run each printed `all checks passed` with all
six sections; the publish committed `f9d732b` and section 4 went back to `ok — identical`.

**Risks learned:** **a limitation already written down is only useful in the direction you read
it.** p8.31 recorded, the day before, that "a reflog keeps an abandoned commit reachable, so
section 6 is weakest right after the mistake". Read from the other end — a reflog that holds
objects in the source makes them unreachable in a clone of it — the same sentence predicts this
exactly. Both `docs/records/known-limitations.md` and `docs/engineering/layout.md` now state it as
cutting both ways. The general form: a blind spot recorded as "X hides Y from this check" should be
read back as "what else does the absence of X invent?"

## p8.36 — The loop assumes a git remote, and dies rather than degrading without one · 2026-11-03 · Alpha-30-creator

**What changed:** seven sites that failed in a fresh `git init` repo with no remote now detect and
**name** the condition before anything needs it, then degrade. `ws-start` §1 reports the remote
state and the upstream state as separate clauses across six measured states — `NO REMOTE`,
`FETCH FAILED`, `behind/ahead N/M`, `no upstream for this branch`, `upstream [gone]`, and the
two-fact case `NO REMOTE … · behind/ahead 0/1` — and it reads the fetch's exit status, which it
previously discarded. `ws-start`'s stale sweep stops testing "holds work" with
`log --oneline @{u}..HEAD`. `ws-plan` §1, its read step and its §5 branch-cut each resolve the ref
they can actually use and print it, with `LOCAL REF ONLY` when that is the local one. `ws-review`'s
gather does the same and gained `NO BASE REF`, `HEAD IS <base>` and `NO COMMITS YET`; its step 5
stopped promising that `fetch -q` proves anything; and *Before anything* gained a stated branch for
a project absent from `device.yaml`.

**Decisions:**
- *In scope beyond the three sites the criteria name*, both under criterion 1's "any command that
  needs one": the stale sweep, whose `log @{u}..HEAD` exits 128 with **empty stdout** — the same
  empty stdout that means "nothing unpushed" — so a worktree holding commits that exist nowhere
  else reads as holding no work and is offered for removal; and `ws-plan` §5's `pull --ff-only`,
  which failed at exit 1 while the next line created the branch anyway from an unknown base. The
  first is the only work-losing path in the task.
- *Rejected: a shared `remote-preflight` file the three skills link to.* Same reason p8.13 rejected
  a shared loop snippet — a delivered body must stand alone, and an agent that does not open the
  link gets nothing.
- *Rejected: `2>/dev/null || true` per site.* That makes the failure quiet rather than named, which
  is the defect, not the fix.
- *Rejected: more code to tell one `rev-list` failure from another.* An unborn or orphan HEAD whose
  upstream ref does exist reads as `[gone]`. Narrow, and a mislabel rather than a silence.
- *Rejected: weakening the retirement guard* so a remoteless project can retire a track. The guard
  refuses a worktree whose branch has no upstream because those commits exist nowhere else, and
  that is correct. Filed as p8.40 with a written decision as its acceptance.
- *Rejected: fixing `git -C <repo>` quoting inline.* Filed as p8.39 — dozens of sites, p8.13's
  class, and it fails loudly rather than lying.
- *Out of scope, per the task's own Notes:* `ws-ship`'s push and PR steps, `ws-wrap`'s push.

**Evidence:** [PR #21](https://github.com/Alpha-30-creator/worksite/pull/21), merged `7ae5dfb`;
library `ff9555f`; published `c5fe36d`. `verify.sh` builds every fixture from nothing, **extracts
the blocks from the delivered copy itself** and runs 23 of them under `bash` — every state of every
changed block, with the header stating which fixtures are shared and which are untouched. The
sweep's old idiom and the shipped retirement logic run side by side against one branch holding a
commit that exists nowhere else. Audit 45/45 under all three agents, 0 broken links, 0 positional
parameters. `bash scripts/check.sh`: all six sections, on the branch, the staged tree and the
target.

**Risks learned:**

*A degrade is new code, and new code written to fix a silent failure inherits the audience's trust
without inheriting the scrutiny.* Round one found two silent wrong answers **inside the degrade
itself**: `ws-plan`'s read step never reset `ref`, so a value left from an earlier run in the same
shell was used silently and the warning suppressed; and with no ref it ran `git show ":<path>"`,
which reads the **index**, returning staged content while the output said `reading at: none`. It
also found a bare `exit 1` that closes a persistent terminal — the identical defect the pack had
already solved with a subshell, reintroduced three sections away from the comment explaining it.
**Third task in a row where the fix reproduced its own defect class** (p8.24 three times, p8.13
twice, here twice). The check that catches it is cheap and now has a name: after writing a degrade,
run it in the state it degrades *from*, then in a state it was not written for.

*A fixture that cannot fail is not evidence.* `ws-review`'s unborn-repo branch hid everything
already staged, because `git diff` alone is the index against the working tree and
`git diff --cached` is what shows staged work — my own comment had them backwards. The fixture
meant to prove that branch held a single untracked file, so it could never have caught it. Writing
the fixture and the code from the same wrong mental model is how a green run means nothing.

*Correcting an over-claim under pressure reproduces it somewhere new.* Three of the nine false
statements review found were in evidence I had **just regenerated for over-claiming**: "a fresh
fixture per state" (true of one section), "verbatim" for logic that is retyped, and an `exit: 0`
that was an echoed literal rather than a measured status. Fourth task running with this class, and
the second where it reached the artefacts rather than the commentary. What changed as a result:
`02`'s header now states what is shared, and `03` prints a measured flag instead of a sentence.

*A filed task with a false premise is worse than no task.* **p8.40 was pushed to `main` resting on
a claim that a local-only project can never retire a track.** Review disproved it by setting a
local upstream, and noticed the guard only loops over the track's worktrees, so a
`worktrees: false` track is never checked at all. Corrected in `af0bbfb` before the ship. The
board is read before every claim, so a wrong Why propagates into whoever picks the task up.

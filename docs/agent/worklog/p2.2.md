## p2.2 — Translate the fourteen skills, do not strip them · 2026-11-01 · @Alpha-30-creator

**What changed:** all fourteen skills now live in `skills/` and name no real project, repo,
person, device or path — 46 files, 70 private lines across 23 files reduced to zero. Three
invented example projects were added at `ws-shared/examples/`, and `ws-shared/reference.md` was
split: its rules stayed, its device values became examples. The library holds the same content, so
publishing can be a plain copy.

**Decisions:** the rule was *translate, do not strip*, and the classification carried the task.
Of 70 lines, ~48 were bookkeeping ("Serves repo-x") replaced by the rule that *selects* the pack;
3 were pointers into private docs replaced by the mechanism; 6 were voice; 8 were device values
that split out; **five were real worked detail** and only those needed care. Both the bookkeeping
and the pointer classes came out better than they went in — a "Serves" list is wrong the moment a
repo is renamed, and a hardcoded doc path helps nobody including its author.

*Rejected: anonymising the worked detail.* Blurring "a repo running LangGraph with `routing.py`
and `tiers.py`" into "an AI service" would have destroyed the only thing making the pack worth
reading. Re-cast against an invented project at equivalent specificity instead.

*Rejected: keeping a "Known project ids" list anywhere.* A written-down inventory is wrong the
moment a project is added. `device.yaml` is the authority; the pack now says to read it.

*Rejected: a bare `/Users/` leak pattern.* It blocked the pack's own invented `device.yaml`,
which must show a realistic absolute path to teach anything. Narrowed to the author's own home
paths and verified in both directions; the broader "no hardcoded local paths" rule moved to
`ws-refine`, where judgement can be applied instead of grep.

*Rejected (by the review, correctly): neutralising `"HK$1,200.00"` in the money pack.* The right
fix for a concrete detail with no home is to **give it a home** — northwind is now priced in HKD
and the detail stayed verbatim. The same reasoning as the task's own rule, arriving from the
other direction.

**Evidence:** `scripts/check.sh` zero on all three sections, with **section 2 running for the
first time ever** — no `skills/` directory had previously existed, so frontmatter had never been
validated. Library and repo verified `identical across all 14` by per-directory diff, which is
the property ADR 0001 rests on. `examples/` confirmed present on all three agents individually,
applying p8.9's lesson rather than trusting the library-only audit. Full record in
`records/`-adjacent track evidence; the review table is reproduced in the roadmap.

Independent review in a context that had not done the translation: **8 findings, all 8 verified
against the files by grepping the quoted lines, none overturned.** The feared failure — losing
concrete detail — did not happen; both highest-risk packs still carry detail nobody could have
written generically. What it found instead was the inverse: two mechanisms that led nowhere, one
rule contradicting the examples, and two files where repo facts were kept verbatim without an
anchor. **Three of the eight were rules this session wrote hours earlier, broken by this
session** — which is the whole argument for the review step existing.

**Risks learned:** the leak scan matches names, not voice. A manual pass found `ws-setup` still
reading "the docs carry **his** way of working" after the line above it was fixed in the same
edit. Already noted in `risks/common.md`; now demonstrated. Second: an example without a
currency, a framework or a domain leaves rules unanchored — findings 4, 6 and 8 were all the same
defect, and the fix was to make the examples more specific rather than the packs more vague.

**Docs touched:** `skills/` (new, 46 files), `docs/roadmap/P2-depersonalise.md`,
`docs/STATUS.md`, `scripts/check.sh` (two real bugs fixed: template placeholders treated as
links, and untracked files silently skipped — a false pass), `scripts/leak-patterns.txt`.

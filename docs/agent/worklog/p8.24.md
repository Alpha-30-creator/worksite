## p8.24 — Gates that read an empty result as a pass · 2026-11-02 · @Alpha-30-creator

**What changed:** `ws-refine`'s graph audit rebuilt around one rule — **each part carries a
denominator into the verdict, and the verdict is unreachable unless every denominator is positive
and consistent.** Part 8 is now a gate rather than a printer, so `0 findings` and `0 read` are no
longer the same output anywhere. Plus the two other silent-pass sites (`ws-shared/trackers/roadmap-files.md`'s
board read, `ws-setup`'s `find`), one new universal as entry 15 of `tier1-universal.md`, and three
documents. Four library files; the repo's `skills/` followed by publish, per ADR 0001.

**Decisions:**
- **Rejected `cd … || exit` as the fix for the first defect, then corrected the reason.** The lead
  first claimed a `cd` guard would not catch the reproduction; it would. What a `cd` guard cannot
  catch is a `cd` that **succeeds** into a library that is not the real one — a redirected `$HOME`
  or a symlink aimed at the published artifact. Identity therefore compares the cwd against the
  store path `agent-sync doctor --json` reports: two independent sources.
- **Rejected the approved plan's identity assertion, which was circular.** It compared the library
  path with itself (`[ "$(pwd -P)" = "$(cd "$lib" && pwd -P)" ]` after a guarded `cd`), which
  passes wherever the `cd` landed. The builder caught this and departed from the approved plan
  deliberately; the departure is strictly stronger.
- **Rejected `set -e`**, and said why in the block, because it is the first thing anyone will reach
  for: a clean part ends on `[ -n "$x" ] && printf …`, which returns non-zero precisely when there
  are no findings, so `set -e` would abort the audit exactly when it is clean. Positive counts are
  the only route.
- **Rejected reading `ok`, `exitCode` or `targets[].state` from `agent-sync`.** Measured: `ok` is
  `true` with 19 artifacts drifted; `exitCode` was **3** because of 19 drift rows belonging to
  other projects, so a gate keyed on it would abort every `ws-*` audit for an unrelated reason;
  `targets[]` carries no state field at all. The gate reads `operations[]` filtered to `skill/ws-`.
- **Rejected rewording the comment that tripped the reverse check**, in favour of excluding fenced
  code from the scan. The check's definition is "an exit the *prose* offers", and a comment inside a
  shell block is not prose — the scan's domain was wrong, not the sentence. Measured before
  accepting: the exclusion drops exactly the one fence-only finding and both true positives survive.
- **Rejected chasing the last residual shape.** A failure that corrupts a denominator while leaving
  it positive is a wrong-answer class rather than a silent-pass one, and outside this task's
  criteria. Named in ADR 0004 instead.

**Evidence:** PR #15, CI green in 16s. The certifying post-deploy run is
`verify/Z1-certifying-run-post-deploy.txt` — the audit block extracted verbatim from the deployed
`ws-refine/SKILL.md`, after `agent-sync save` reached claude, codex and cursor:
`auditing 14 of 14`, `part 3 parsed 14 · part 4 resolved 14 names · part 5 read 45 files, 9 links ·
part 6 checked 13, scanned 13`, `deployed check: claude 45/45 · codex 45/45 · cursor 45/45`,
`deployed check complete`, exit 0. Pre-deploy the gate correctly **aborts** (`B8`, nine lines, exit
1, with `ok = True | exitCode = 3` beside it) — which is why no builder could produce the
certifying run. `publish.sh` published as `f5f84c0` and §4 returned to `ok — identical`.

**Risks learned — the finding worth keeping:** **the fix reproduced its own defect three times, and
each was caught by the assertion added for the previous one.** (1) the unguarded `cd` certifying the
published artifact; (2) part 7's deployed check inside a command substitution, so `SystemExit` ended
the Python and the verdict printed `0 missing under an agent` at exit 0; (3) a variable named `st`
colliding with part 1's JSON that part 7 reads, caught only by the sentinel added for (2). The
generalisation, now entry 15 and ADR 0004: **a check composed of parts that cannot fail the whole
will default to reassuring output at every seam.**

Two process lessons, both the lead's: a reviewer reading a branch cut before a tracker edit filed
two false Must-fixes, because the brief never said the tracker had moved — every later brief named
the tracker commits; and recording each library diff into `verify/` as the work proceeded is what
made an API-failure mid-run recoverable, since the library is not a repo the worktree commits to.

**Honest limits, all in the documents:** recall is low — 12 unlisted pairs exist that the reverse
check never reports. An exit offered only inside a fenced example is invisible. `agent-sync` must be
runnable or the audit aborts rather than degrading. GNU `find` untested; the `rc` contract was
checked on BSD only. The audit over its own source is closed by library-independent fixtures, not by
any live run.

## p8.1 — Make every skill model-invocable · 2026-11-01 · @Alpha-30-creator

**What changed:** the thirteen workflow skills lost `disable-model-invocation`, so the loop now
runs when the work calls for it instead of when someone remembers to type a command. All thirteen
descriptions were rewritten to state what the skill **ends with**, which is what the model
actually triggers on. `ws-env` gained a read-only gate, `ws-ship` and `ws-fanout` had their
triggers narrowed, and `ws-refine` gained three new rules.

**Decisions:** the argument for doing this at all is the pack's own — the journal rule says
anything depending on someone remembering is not there when it matters, and the loop itself
depended on exactly that.

*Rejected: flipping the flag alone.* `ws-refine`'s frontmatter rule **required**
`disable-model-invocation: true` on every workflow skill, so without changing that rule the next
skill it wrote would have re-added it and quietly undone the change. Removing the flag is five
minutes; the real work was fourteen descriptions and the rule that generates them.

*Rejected: making `ws-shared` invocable too*, despite "all of them" being the instruction. It is a
reference pack read by path, not a skill — auto-invoking it adds a competitor to the trigger space
with nothing behind it. `agent-sync` refused the deployment, which was the signal. `ws-refine` now
records the exception so a future agent does not strip it again.

*Rejected: shipping the flag change without safety gates.* Auto-invocation removes the typed
command that used to serve as confirmation. `ws-env` could have decrypted credentials to disk
during an unrelated task; it now runs read-only status unless asked for by name. `ws-ship` merges
and closes, `ws-fanout` spawns up to five subagents — both now require explicit intent.

**Evidence:** zero of thirteen descriptions stated an end state before; thirteen do now. Twelve
collision-prone phrases each resolve to exactly one skill — "a workflow step felt wrong" to
`ws-refine`, "too big or unclear" to `ws-task`, "fails for an unknown reason" to `ws-debug`.
Verified per agent rather than from the library alone, applying p8.9's lesson: 13/13 on Claude,
Codex and Cursor, no drift. `ws-refine`'s graph audit clean.

**Not verified:** real trigger behaviour. The collision matrix is a desk check, and the author of
a description is the worst judge of whether it fires. Only ordinary use will show that.

**Risks learned:** `ws-env`'s description named the author — a breach of the
generic-means-generic rule added hours earlier in the same session, found by a check rather than
by reading. Reinforces the risk already in `risks/common.md`: the leak scan catches names in
bodies, and nobody had thought to scan frontmatter.

**Docs touched:** `docs/roadmap/P8-pack.md`, `docs/STATUS.md`. The skill changes live in the
agent-sync library per ADR 0001.

**PRs:** none. Library changes committed and pushed there; this repo carries the record.

## p4.3 — Repo furniture · 2026-11-02 · @Alpha-30-creator

**What changed:** `CONTRIBUTING.md`, `SECURITY.md` and `CODE_OF_CONDUCT.md` exist, and
[`.github/workflows/check.yml`](../../../.github/workflows/check.yml) runs `bash scripts/check.sh`
on pull requests and on pushes to `main`. `README.md` gained the three links it had been naming in
prose, and [`../../engineering/layout.md`](../../engineering/layout.md) gained the four paths and a
paragraph on what the CI run does and does not do. Shipped in a two-track fanout batch with p8.5.

**Decisions:**
- **No email contact in `CODE_OF_CONDUCT.md`.** Covenant 2.1 requires a contact method, and the
  maintainer's name *and* address both match `scripts/leak-patterns.txt` while that file is not in
  `check.sh`'s exclusion list — so an address would have made the file uncommittable. Rejected:
  widening the exclusion list, which would have put a real address in a public repo and weakened
  the one guard that cannot be undone after the fact. Chosen: the issue tracker plus GitHub's
  private advisory route.
- **CI triggers on `push: [main]` as well as `pull_request`,** because ADR 0002 lands publish
  commits directly on `main`; a PR-only trigger would have left the publish path permanently
  unchecked. Rejected: PR-only.
- **`cancel-in-progress` narrowed to pull requests.** A superseded PR run is noise; a superseded
  push-to-`main` run is the only after-the-fact leak signal for the commit it was started for.
- **Working-tree mode in CI, not `--staged`** — strictly broader, and it closes the blind spot
  where a link to a present-but-unstaged file passes the hook and breaks on a fresh clone.
- **The gap table's count was dropped** rather than decremented, because two separate tasks
  (p4.2 and this one) each reduce it and a number appearing twice is a claim about arithmetic.
- **`CONTRIBUTING.md` says pull requests are not accepted,** which follows from ADR 0001 — the
  skills are authored in the maintainer's library and this repo is a published copy, so a patch
  against `skills/` is overwritten by the next publish. Half a sentence explains why the
  `pull_request` trigger is not a contradiction: this project's own tracks merge through PRs.
- Rejected along the way: a bullet claiming `git add -A` would pick up workspace state (false —
  `.worksite/` and the journal are gitignored; rewritten to the real reason, that a blanket add is
  one removed `.gitignore` line away from committing them); restating `layout.md`'s provenance
  table in `CONTRIBUTING.md`, which would then drift from it; adding the three root files to the
  README's `## Documentation` list, where they do not belong; linking `INSTALL.md`, which is p4.2's
  criterion and would fail §3 today.

**Evidence:** [PR #8](https://github.com/Alpha-30-creator/worksite/pull/8), merged as `7bf04e2`.
`bash scripts/check.sh` exit 0 on the branch tip, §1–§3 `ok` (§4's three differences were p8.5
editing the library concurrently, and §4 never fails). Criterion 4 was proved by the PR's own
`check` run — pass in 5s — which is the only way a workflow can be proved before it merges. The
same script was run with `HOME` pointed at a directory holding no agent-sync library, to confirm CI
would not go red on a fresh clone: §4 printed `skipped — no local library on this machine`. The
workflow YAML was parsed after the fix round (Ruby psych; PyYAML is absent on this machine) and
`on:`, `concurrency` and the step chain all resolve as intended. **Not proved:** that a red check
blocks a merge — it does not, without branch protection, which is p1.2's.

**Risks learned:** the sharpest one is the class the review kept finding — *a sentence describing
what a check covers is true of one mode of that check and reads as true of all of them*. Four of
the five review findings were that shape. Proposed as a line for `risks/common.md`; see the
batch's follow-ups.

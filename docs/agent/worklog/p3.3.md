## p3.3 — Write the extension guides · 2026-11-02 · @Alpha-30-creator

**What changed:** three new pages under `docs/engineering/` — `trackers.md` (205), `stacks.md` (145),
`layout.md` (110). No existing file modified. The pack's central claim is that adding a tracker or a
review pack never edits a skill; these make it actionable.

**Decisions:**
- **The worked example is the hard case on purpose.** `driftwood`, a fictional hosted board with **no
  claim lock**. *Rejected:* a file-based example — the four questions are trivial for a file in a repo
  and two shipped adapters already demonstrate it. The question that bites is *claim*, and only
  without a lock does writing it force the author to say there is no lock, carry the
  re-read-and-stop step, and handle a board state the cartridge has no key for by **asking** rather
  than inventing one. A file-based example lets all three go unwritten and still look complete.
- **A job sentence and an explicit "what is not on this page" line per page**, with an ownership
  table assigning each reader question to exactly one page: keys to the schema page, direction of
  travel to `sync-direction.md`, how-to-work-here to `AGENTS.md` and the cartridge, arguments to the
  concepts page. *Rejected:* one combined `extending.md`, and re-documenting `tracker.kind`.
- **The adapters are presented as non-uniform**, because they are. Two authoring gaps named as open
  (p8.20) rather than papered over, and the `lite`/tracker contradiction named as open (p8.22) rather
  than resolved in a guide.
- **No `R`-number defined, and `R3` never cited.** The labels are cited across the library and
  defined nowhere in it, and `R3` means "unknown keys are ignored" on the schema page against "an
  unknown kind is not an error" in the adapter index. `R4` is cited by label only; the unknown-kind
  behaviour is stated in words. *Rejected:* defining them here — a guide is not the place to settle a
  label set, and doing so would have deepened the collision.
- *Rejected:* `file:line` citations and hard counts. `docs/engineering/` is living-fast, where stale
  means confidently wrong; the shipped adapters and the always-on review files are listed, never
  counted.
- *Rejected, on the review's nit:* reproducing the checker's inline allowlisted string. It contains
  one of the guard's own patterns, and a page does not need to carry it to point an auditor at the
  right line — the row names the location and the category instead.

**Evidence:** PR #5. `bash scripts/check.sh` green, and again via the hook on the staged bytes. All
37 relative targets resolved individually rather than trusted to the checker. Review verified roughly
twenty mechanism claims against the library rather than against the pages — the four questions,
`R4`'s consistency across three files, the tag table living in `reference.md` and in **no** skill,
deduplication, per-repo selection, the always-on set, the pack shape, `stack: []` selecting nothing,
and the claim-lock asymmetry row by row — and killed three of its own draft findings by checking
them. Its verdict on the example: an agent handed only that adapter could claim and ship.

**Risks learned:** one, about the checker rather than the pack. **A coverage claim about a script
reads exactly like a right one.** `layout.md` asserted the link section checks `scripts/publish.sh`;
it skips every non-`.md` file, and the page's own section row said so two sections down. This is the
citation-drift class already recorded after p3.1, in a new shape — the existing risk line should say
"a claim about what a check covers" alongside "a `file:line` citation". Filed as a widening.

**Also found while writing:** the link checker treats a bracket-paren link written inside prose as a
real target, because its extraction has no fence awareness — this worklog entry tripped it while
describing it, which is as good a demonstration as the finding could ask for. It failed the build, was reworded, and
the blind spot is documented on the page.

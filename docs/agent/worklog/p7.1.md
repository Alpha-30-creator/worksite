## p7.1 — Dry-run the install as a stranger · 2026-11-02 · @Alpha-30-creator

**What changed:** a dated record of two agents installing the pack from `INSTALL.md` alone —
**44 guess-points**, 18 inside `INSTALL.md`'s own eight steps — plus five fixes to `INSTALL.md`,
three limitations, two new tasks and one criterion on an existing one. **The loop itself ran end to
end, unaided**, on a real one-file task in a throwaway CLI one of the agents built: `ws-setup`
through `ws-ship`, worklog harvested, track retired, tracker marked done, follow-up filed.

**Decisions:**
- **The stranger could not be the author.** Criterion 1 asks for "nothing the author happens to
  know", and the author cannot un-know it — every ambiguity would resolve silently against memory,
  which is the failure the criterion exists to catch. Two subagents with none of the conversation,
  the same independence trick `ws-review` uses. **Rejected: running it myself.**
- **Rejected letting them use the default store.** A real stranger runs `agent-sync setup` and
  creates `~/.agent-sync/store`, which here is the live library holding 73 skill directories across
  six projects. Both got a forced `--store`, recorded in the record as a stated deviation rather
  than hidden. It cuts both ways: a stranger would not do it, and it is the harder path — p4.2's
  guard was hardcoded to the default until review caught it, so this was that fix's first live test.
- **Rejected the summary as evidence.** A subagent transcript cannot be read without overflowing
  context, so each wrote a log file continuously and the log is the evidence. **And rejected leaving
  the eighteen only in those logs** — `ws-ship` deletes them, so they are enumerated in the record,
  or the headline number would have become unsupported the moment the track was retired.
- **Rejected a task per finding.** 44 findings cost the board **net +1**. The eighteen `INSTALL.md`
  items became fixes here, because criterion 3 asks for a fix where one is possible and `INSTALL.md`
  is a repo file. The adapter gap became a criterion on the existing **p8.30** — it is that task's
  mechanism, who crosses from library to deployed and what it costs — rather than a third task.
  Five became limitations. Two tasks filed: **p8.35**, **p8.36**.
- **Rejected merging p8.35 and p8.36.** One is a substitution bug, the other a remote assumption:
  a theme, not a mechanism, and theme-merging is what the 2026-11-02 trim fought.

**Evidence:** PR #16, CI green in 8s, `check.sh` exit 0. The loop run is real — eight commits in the
throwaway repo, a task claimed, planned, built, merged, harvested and marked done, with `t-3` filed.
Both documented counts exact: 3 questions with no cartridge, 4 with no adapter. R4 held — a complete
adapter for an invented tracker kind with zero skill edits, verified by `diff -rq`.

**Risks learned — three defects, each reproduced by the lead before recording:**
1. **A `$1` in a skill body is replaced by the caller's argument at delivery.** `ws-env`:51 and
   `ws-sync`:18 are byte-perfect on disk; the corruption is only in the copy handed to an agent that
   invoked the skill *with arguments*. `ws-env pull` then prints a plausible, specific, wrong
   `skip <project> — not linked on this device` for all 28 manifest rows, writes no credentials, and
   exits clean. **No author test finds this**, because the trigger is the author's own habit of
   passing a track id. → p8.35
2. **`ws-sync`'s sweep enumerates children of the workspace root**, so a project whose root *is* the
   repo contributes no rows and no message. Applies to this repo. → p8.35
3. **The documented adapter path does not make an adapter readable** — authoring is the library,
   reading is the deployed copy, only `save` bridges them, and nothing says so. The author's own
   test passes because the author's library is already deployed. → p8.30

**The lesson that is about me, not the pack:** the independent review's two sharpest findings were
wrong claims I had written into the published install doc while fixing it. `--no-push` does exist on
`save`, and `adopted` means the agent's copy already **matches** the library — the opposite of what I
wrote. The second was my own machine's state (it already had `ws-*` installed) generalised into a
rule a stranger would have been taught; on a fresh machine the state is `missing`. Fixing a document
against a stranger run, from the author's machine, reintroduces the author's assumptions.

**Also learned, operationally:** the pre-commit hook refused the tracker commit because p8.35's
Notes linked a record not yet on `main`. The guard was right; the order is record-first, the same
ordering p8.24 met. And `gh pr merge` was denied by the harness as *Merge Without Review* — not
worked around, escalated.

**Honest limits, in the record:** two agents are not a population, so this shows the install is
followable and not yet clear. The forced `--store` is a deviation. The post-run hash check covers 73
top-level `SKILL.md` files, not every file in the library. **Three documented steps cannot be run in
a sandbox at all** — `ws-sync` step 1, `ws-env pull`, `agent-sync save` — so a cautious first-time
user cannot trial this pack without writing to their own machine.

**agent-sync's own tracker now owes three items**, none of them worksite's: `add skill` destroying a
destination with no guard, its skill pack naming a `healthy` field `doctor --json` does not emit, and
`link` reporting "not a git repository" on a directory that is one.

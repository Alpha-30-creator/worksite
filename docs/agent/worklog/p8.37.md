## p8.37 — `ws-refine`'s own audit cannot be run as delivered, and part 3b then reports zero · 2026-11-03 · @Alpha-30-creator

**What changed:** the graph audit moved out of `ws-refine/SKILL.md` into `ws-refine/audit.sh` in
the library, run as `bash "$HOME/.agent-sync/store/skills/ws-refine/audit.sh"`. Part 3b gained a
compile probe, a status check and a count that only increments after a scan that ran; it now scans
the **whole** `SKILL.md` rather than fenced blocks only, and no longer excludes `$0`. Parts 2, 3,
3b and 6 gate on `[ -f ]` as well as `[ -r ]`. `scripts/publish.sh` gained a `PACK_EXEC` list so
the pack can ship exactly one named executable. ADR 0005 records the decision and what it
overturns.

**Why it mattered:** every pack task carries "changed through `ws-refine`, with its graph audit"
as an acceptance criterion, and the audit could not be run as delivered. A skill's body has the
caller's argument substituted into its positional parameters, the audit's awk programs use `$0` as
a field reference, and so invoked as `/ws-refine <anything>` — the only way anything here invokes
it — `if($0!="---")` arrived rewritten and would not parse. Part 3 died loudly enough to survive.
**Part 3b died silently**: no findings reported, its per-file count already incremented before the
scan, part 8's floor and cross-check both satisfied. A clean verdict over a scan that never
happened, in the part p8.35 added to catch exactly that. And the audit could not see it about
itself, because part 3b excluded `$0` deliberately — correctly, which is what made the blind spot
structural.

**The hazard, counted** (criterion 4 asks for the result as a count; this is it). Across every
`.md` in every `ws-*` directory of the library:

| | before | after |
|---|---|---|
| executable positional parameters in a `SKILL.md` | **3** — `ws-refine/SKILL.md`:239 ×2, :265 ×1 | 0 |
| comment-only mentions inside a fenced block in a `SKILL.md` | 6 — `ws-refine` ×4, `ws-env`:51, `ws-sync`:18 | 0 |
| **prose** mentions in a `SKILL.md` | 1 — `ws-refine`:102, the sentence defining the rule | 0 |
| occurrences in a reference page | 3 — `ws-shared/tracks.md` ×2, `ws-shared/reference.md` ×1 | 3, **correct** |
| `$@`, `$*`, `$#` anywhere | 0 | 0 |

The three reference-page occurrences are legitimate and must not be "fixed": nothing substitutes
into a file an agent opens with a file tool. Confirmed independently by the reviewer's fresh
invocation — only `SKILL.md` is delivered, and `audit.sh` sits beside it undelivered.

**Decisions:**
- **A file, not a rewritten block.** *Rejected:* restructuring the awk to avoid `$0`. There is no
  whole-record alias in awk, so it means losing `printf … NR, $0` entirely — and it would fix
  three tokens while leaving the class, with part 3b still having to exclude `$0` to avoid
  flagging itself.
- **The library path, not the skill's base directory.** *Rejected:* `"<base dir>/audit.sh"`. The
  harness does print it, but it differs per agent, is absent in some clients, and would have an
  agent audit the library using a copy that may be one `save` behind it.
- **`bash <path>`, not a shebang execution.** No execute bit has to survive a copy or a publish.
  The deployed copies are `0644`, which is exactly why this matters.
- **A named list in `publish.sh`, not a flag.** *Rejected:* `--allow-extra`, which exists for this
  and lifts the refusal for *every* file in the run — a stray `.env` in the same publish would
  pass beside the file it was meant to allow. *Rejected:* a `*.sh` glob, the same failure one
  level down.
- **ADR 0005 rather than editing two ADRs.** They are immutable here and carry `Supersedes`
  fields. It overturns ADR 0004's rejection (its reason — a personal library path travelling into
  published copies — does not apply, measured: no hardcoded `/Users` or `/home`, no pattern hit)
  and two of ADR 0002's three objections, and **accepts the third on the record**: `audit.sh` is
  published into the repo it is published by, so a bug in it reaches every reader of the pack.

**What review caught, and it was the sharpest possible instance.** The commit fixed this class
twice in other files — and left it in `ws-refine/SKILL.md`:102, the sentence *defining the rule*,
which wrote a positional parameter out as its example and was therefore delivered with the
caller's argument in its place. The rule lost its own subject, in the skill that owns it. Part 3b
could not catch it because it scanned fences only; a reviewer invoking the skill and reading what
arrived could, and did. That is now the reason part 3b scans whole files.

Second: `[ -r "$f" ]` admits a **directory** named `SKILL.md`, and awk over a directory exits 0
having read no records — so that skill's scan found nothing, reported nothing, and still
incremented every count. The same clean-verdict-over-nothing shape, surviving the fix for it.
Measured on BSD awk 20200816.

**Evidence:** the pre-fix delivery was reproduced **twice in one session with two different
argument strings** (`$0` → `p8.31:`, then `$0` → `p8.37-delivery-probe:`), which is what
establishes that the substitution is positional and indifferent to content. The post-fix delivery
**could not be read from the session that made the change** — the harness serves a cached body for
an already-loaded skill, which is itself why reproduction 2 showed pre-fix text after the fix was
deployed. It was delegated to a fresh context, which read the Audit section byte-identical to the
library file with the `bash "$HOME/…"` line intact and zero positional parameters — and in the same
read found `:102`. The contrast was then measured rather than argued: same corruption applied to
the pre-fix shape printed `VERDICT … part 3b scanned 14 … 0 positional parameter` at exit 0, while
the post-fix shape printed `AUDIT ABORTED: part 3b's scanner does not compile` and no verdict.

**Risks learned:**
- **The publish guard refuses a new kind of pack file, and that inverted the plan's order.**
  `publish.sh` classifies everything in a skill directory and refuses what is neither Markdown nor
  known reference data. So the `PACK_EXEC` change had to be **merged to `main` before** the publish
  could run, because publish runs the target repo's own copy of the script on `main` — the plan had
  said publish first. `§4` parity reports differences for the whole interval, which is legitimate
  mid-change and informational by design.
- **A check's gate can admit the wrong kind of filesystem object.** `[ -r ]` on a directory is
  true, and awk reads it as empty rather than erroring. Any check that reads files by glob wants
  `[ -f ]` too.

**Recorded, not closed:** the compile probe catches a program that fails to **parse**, not one that
is valid and wrong — unreachable through the delivery channel now, which is the actual reason the
fix works, and stated that way in `layout.md` rather than overclaimed. Nothing proves an agent runs
the file instead of reconstructing the block, and a stale **deployed** `audit.sh` is caught by part
1 only when the library has moved. A CRLF `audit.sh` loses `set -u` and `pipefail` and continues at
exit 0. All three in `docs/records/known-limitations.md`.

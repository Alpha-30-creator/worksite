## p8.2 — Teach review and planning where documentation belongs · 2026-11-01 · @Alpha-30-creator

**What changed:** a new always-on review pack, `ws-shared/review/documentation.md`, that decides
*where a piece of writing belongs* rather than how much of it there should be. `tier1-universal.md`
check 7 split into wrong-content and right-content-wrong-place, and its severity table rewritten.
`ws-plan` step 11 turned from a list of destinations into a decision carried as an acceptance
criterion. Deployed to all three agents.

**Decisions:** the defect was never that the rule was missing — check 7 already covered comments.
It was that the severity table filed comments under `Note`, which "never blocks", so every finding
was unactionable by construction. Fixing that one row is the change that makes the rest bite.

*Rejected: "write shorter comments", and any length or density rule.* The survey disproved it. The
two worst specimens are **well-written prose** — that is why they survived review — and the same
two repos contain 682 exemplary docstrings. A length rule would have destroyed the good writing
and missed the real defect. The discriminator that works instead: *would a reader at this line
need this in order to change the line correctly?*

*Rejected: putting this in `ai-slop.md`.* Over-explanation is a genuine agent-written-code smell
and that pack was a natural home, but two packs owning one rule is how rules drift apart.

*Rejected: reporting these as "delete this comment".* The content is almost always worth keeping,
so a finding has to name a destination and say what stays behind, or it will be ignored —
correctly.

**Evidence:** validated against three specimens, recorded in
`records/2026-11-01-documentation-pack-validation.md`. The pass condition was **discrimination,
not detection** — a pack that flags all three is as broken as one that flags none. A 39-line
comment over one constant flagged on all five detectors at `Must fix` (it asserts "until today"
against a date three weeks old). A 35-line mixed header flagged on its narrative while its usage
block and contract were left alone — one comment, two different right answers. Two exemplary
docstrings not flagged at all. `ws-refine`'s graph audit clean; pack present and referenced on all
three agents.

**Risks learned:** none added to `risks/` — the rules themselves are the output. One process
finding recorded separately as p8.9: the graph audit reported clean while the pack was missing from
one agent's deployment, because the audit checks links *within the library* and not whether a
referenced file actually reached each agent. A reference to a file an agent cannot read is silent
at runtime.

**Docs touched:** `docs/records/2026-11-01-documentation-pack-validation.md`,
`docs/roadmap/P8-pack.md`, `docs/STATUS.md`. The pack changes themselves live in the agent-sync
library per ADR 0001; they reach this repo when p6.1 builds the publish step.

**PRs:** none. Library changes committed and pushed to the library repo; this repo carries the
record only.

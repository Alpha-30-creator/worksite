## p8.34 — `ws-setup`'s profiles, and the cartridge keys it writes · 2026-11-03 · @Alpha-30-creator

**What changed:** the profile ladder became **three rungs chosen by a question** — `lite` (6
questions), **`standard`** (14, new), `full` (21) — numbered continuously so each rung is the one
below plus its own. `ws-setup`'s mode table lost the row that inferred the profile from folder
shape. Five keys that promised what nothing delivered were settled: `git_flow.merge_style` and
`rule_prefix` are now written by the template and documented with their read sites,
`house_rules.owned_by` was narrowed rather than reversed, `machine:`'s notes-only rule gained the
worked example its criterion names, and `artifacts`/`agents_file` are asked for the first time.
`risks/common.md` is no longer seeded empty — `ws-review` creates `risks/` when it has a first
risk. `tracker.kind: none` gained a stated path, defined once in `ws-shared/trackers/README.md`.
Repo-side: the schema page's `profile` enum, two key rows, and **Known gaps from three rows to
one**.

**The measurement that reshaped the design, before anything was written.** The missing rung looked
like "the long-lived single-repo case", and the obvious names for it — `single`, `solo` — are
wrong: **this repo is a single repo carrying `profile: full`**, correctly, since it earns
`decisions/`, `records/` and `engineering/`. The axis is *how much writing the project earns*, not
repo count. Naming it `standard` and saying so in the skill is what stops the next reader
re-deriving it.

**Decisions:**
- **Mode is inferred, profile is asked.** The filesystem answers *what is already here*; it cannot
  answer *how long this will live*, and a weekend experiment and a five-year product look
  identical on disk. *Rejected:* a better heuristic.
- **The three rungs are one continuous enumeration.** *Rejected:* three parallel lists, which is
  what `full` already was — it read "all of standard, plus…" while silently dropping `state_dir`,
  `worktrees` and `merge_style`, and that is why this project had `merge_style` unwritten.
- **`lite` keeps its instruction files and its track directory.** *Rejected:* the smaller `lite` an
  earlier draft produced by accident, which left a project with no file pointing at the one file it
  writes. Criterion 2 asked for a third rung, not a smaller first one.
- **`owned_by` narrowed, not reversed.** Reversing turns a silent permission into a silent refusal,
  which is harder to notice; both read sites now state which branch they took.
- **`rule_prefix` is required on `full` *where the project earns rule skills*.** *Rejected:* plain
  "required", with `null` meaning an unfinished interview — refuted by this repo's own cartridge,
  which is `full` and deliberately earns none, and by the schema's own §13 example.
- **`kind: none` is defined once**, as a four-row table where `kind` is selected, with one-line
  pointers from the four skills that would consult an adapter. *Rejected:* the single paragraph in
  `ws-start` that an earlier round produced, which claimed "everything downstream is unchanged"
  while four later steps of that same skill consult an adapter.

**Evidence:** `.worksite/tracks/p8.34/verify/ten-criteria.md` — every criterion with its measured
before and after, the three rounds' findings, and the hand-verification that replaced a fourth
round: the enumeration counted 1–21 continuous, every count site re-derived from it, the
`kind: none` path checked across all five sites, the old-rule sweep clean but for two historical
quotations.

**Risks learned:**
- **Three review rounds found 11, 12 and 9 must-fixes, and the rate did not converge because the
  fixes were the source.** Ten of round two's twelve were created or left by round one's fixes;
  seven of round three's nine by round two's. **The shape never varied: a structural fix lands in
  the body of a document and misses its summary, its template, or a companion claim written in the
  same breath.** The additive-ladder fix left the *pitch* — the paragraph a user reads to choose a
  rung — still stating the retracted rule, and left the cartridge *template* stating it too, so
  every generated project would have shipped it.
- **A fix can re-create the defect it fixes, one round later.** Round one found `docs_home`
  generated and never asked. Round one's *other* fix, restructuring the interview, replaced the
  git-flow question with a deploy-branches-only one and so made `git_flow.release` generated and
  never asked. Round three found `artifacts` and `agents_file` the same way. **Three instances of
  one class inside one task**, each found by a different round, because nothing enumerates the
  template against the interview.
- **A tidy diff is not a reason.** Inserting the new question as "9b" kept the numbering stable and
  broke the one claim the ladder makes about itself. Renumbered to 1–21 and every count site
  re-derived; "about twelve" and "about thirty" had been loose impressions until the ladder made
  them countable, and then they were wrong by one and by ten.
- **The verification record asserted the claim it declares retracted**, twice, in the same
  document. A record of what was fixed is also a claim, and it is the one nobody re-reads.
- **The graph audit caught a defect on the final commit** — 1 finding to 2, because `ws-task`'s new
  prose offers `ws-setup` and its *What next?* did not list it. One criterion here has an executing
  check behind it; it is the only one that found something without a reviewer.

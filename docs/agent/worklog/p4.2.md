## p4.2 — Write INSTALL.md for an agent to execute · 2026-11-02 · @Alpha-30-creator

**What changed:** [`INSTALL.md`](../../../INSTALL.md) exists, addressed to the agent that will run
it rather than to the user: prerequisites that stop rather than installing runtimes, the store path
read out of `agent-sync doctor --json`, a comparison that runs before anything is written, then
`add skill` per agreed skill and one `save`, ending at `/ws-setup`. A second worked cartridge
([`cartridge-atlas.md`](../../../skills/ws-shared/examples/cartridge-atlas.md)) covers the shape
the first does not: a hosted `trello` board, `artifacts: in-repo`, `owned_by: company`,
`merge_style` set, and a `machine:` block with its inertness stated. The README now points at the
install and has retired its "no install path" gap row.

**Decisions:**
- **The re-run protection lives in the document, because the tool cannot provide it.**
  `agent-sync add skill` calls `copyTree`, which opens with
  `rmSync(to, { recursive: true, force: true })` — no existence check, where `agent-sync new`
  refuses when the id exists. Demonstrated against a throwaway store: a re-run silently reverted an
  edit, **deleted a file the user had created**, and printed `✔ added skill/ws-start to the library`
  either way. So §4 compares first, skips what is identical, and stops on anything that differs
  with the diff shown. Rejected: a wrapper script, because the stop is a conversation; and trusting
  `add skill` to be non-destructive, which the source disproves.
- **The store path is derived, not assumed.** The first draft hardcoded
  `$HOME/.agent-sync/store/skills`. Review caught that on a machine using `agent-sync --store` the
  guard would print `NEW` for all fourteen skills, tell the user there was nothing to lose, and let
  the next step delete their real library. **A guard that fails open is worse than no guard,
  because it is believed.** Now read from `doctor --json`'s `store` field and tested against both a
  default store and an override. Rejected: keeping the assumption with a warning beside it.
- **The second example is atlas, not a fourth invented project.** The examples README already
  describes three projects precisely so a reader builds one mental model; atlas was already defined
  as the hosted-tracker, in-repo, company-owned shape. Rejected: inventing a new name, which would
  have taught a fourth.
- **`machine:` is shown and marked inert.** The schema records that it has no merge semantics and
  no reader. Shown with that stated, rather than omitted, because a cartridge author will reach for
  the shape anyway and an example that hides it leaves them inventing one. The owner chose this
  over omitting it or blocking on p8.33.
- **agent-sync's own prerequisite checks are not restated**, only pointed at. Two copies of a Node
  version check is the duplication this week's trim removed.

**Evidence:** [PR #12](https://github.com/Alpha-30-creator/worksite/pull/12), merged as `16b4c05`,
published as `ebe5217`. Its `check` run passed in 4s. The guard's three outcomes were proved against
a fixture library — 11 `CURRENT`, 2 `NEW`, 1 `DIFFERS`, then 13 `CURRENT` with the edited skill
still flagged and byte-intact — and the destructive re-run demonstrated against a throwaway store.
The store-path derivation was run against both a default store and a `--store` override.
**Not proved:** that a real agent reads §4 and stops rather than running §5 anyway. That is trigger
behaviour, and only a stranger's install settles it — p7.1.

**Risks learned:** the review's finding is worth more than the fix. *My own evidence tested around
the bug*: the fixture used `--store`, so the one line the file actually shipped — the hardcoded path
— was the one line the evidence never exercised. The class is already in
[`risks/common.md`](../risks/common.md) as a check that is claimed to run but is not installed; this
is its sibling, where the test exercises a different code path from the one that ships. Not filed as
a new line, per `ws-task`'s *Where a finding belongs* — it is recorded here, and becomes a risk line
if a third instance appears.

**Two upstream items for agent-sync's own tracker, not this one:** `add skill` destroying an
existing skill directory with no guard, and its skill pack telling agents to read a `healthy` field
that `doctor --json` does not emit (it is `sync`'s). This task transcribed the second one faithfully
before review caught it.

**Docs touched:** `INSTALL.md`, `README.md`, `docs/engineering/layout.md`, and in the library
`ws-shared/examples/cartridge-atlas.md` and `ws-shared/examples/README.md`, republished into
`skills/`.

## p3.2 — Write the concepts page · 2026-11-01 · @Alpha-30-creator

**What changed:** `docs/product/overview.md`, 346 lines — the argument for worksite rather than a
description of it. Eight sections; the four opinions and the four design moves each open on the
failure prevented, give the mechanism, answer a named objection, and where one exists, state an
honest limit. The page the README is to be written from (p4.1).

**Decisions:**
- **Argue, never list.** "It argues for the opinions rather than listing them" is an acceptance
  criterion, so a feature list would have been a failure rather than a style choice. Eight
  claim → argument → objection → limit sections.
- **The strongest evidence is the pack losing an argument with itself** — `ws-ship`'s proposed
  carve-out from confirm-before-delete and its reversal, because a track on disk is visible and
  recoverable while deleted session state is neither. A rule surviving a case where it was
  inconvenient beats any assertion about discipline.
- **Honest limits in the body, not a disclaimer at the end.** The cartridge section names
  `merge_style`, the keys never read by name and the `ws-setup` interview gap, then argues these
  make the case *for* writing the schema down. The tracker section states that only the file-based
  adapters give a real lock, and only when the file is in a repo — a qualification found by checking
  `tasks-file.md` rather than by reading the plan, and it strengthens the argument.
- **Length lost to the criterion.** The plan targeted 270–300 lines; the page is 346.
  *Rejected:* trimming to the estimate — every remaining paragraph in the argument sections *is* one
  of the four required parts, so reaching 300 meant deleting an objection. Failing a criterion to
  satisfy a guess is the wrong trade, and a line estimate is not a gate.
- **The cartridge schema page was referenced in the future tense, unlinked, while p3.1 was in
  flight** — and the filename was removed entirely, not just the tense softened, so the page stayed
  true even if p3.1 had landed narrower or under another name. `check.sh` resolves relative links but
  cannot catch a prose mention of a file that is not there, so the check that would normally catch
  this was unavailable by construction. Converted to real links after p3.1 merged, before this PR.
- *Rejected:* "several keys have **no reader**", which the lead initially asked for and then
  retracted. p3.1's ledger showed only `schema_version` is read by nothing while five more are read
  by concept, so "no reader" was a stronger claim than the truth. The shipped wording carries no
  count at all — mechanism, not inventory, which is what a living-slow folder requires.
- *Rejected:* a thirteen-skill ends-with table (p4.1 owns it; two copies means one goes wrong later);
  documenting any individual cartridge key (p3.1's file); a versus-other-frameworks section
  (unverifiable); an ASCII loop diagram (`sync-direction.md` owns the one diagram); the author's
  first-person voice; and overstating the schema page as making cartridge authoring a solved problem.
- **The thirteen/fourteen contradiction was resolved in the page without touching either
  contradicting file** — "thirteen skills plus a shared reference they all read", which matches
  `README.md` and shipped task p8.1's decision that `ws-shared` stays non-invocable. `README.md` and
  `docs/agent/reference.md` still disagree with each other; filed, not patched here.

**Evidence:** PR #2. `bash scripts/check.sh` green. "Resumes cold" was tested against a nine-point
behavioural checklist, each point marked off with its line, rather than asserted. Every capability
claim was checked against the tree and listed in `verify/read-through.md`; that pass caught the
adapter-locking overclaim. A recorded read-through for authorial voice caught one first-person
instance the leak scan cannot see — the scan catches names, not voice. Independent review: no

third design move its own objection. Links verified to resolve from `docs/product/` specifically,
with the wrong form confirmed not to resolve as a control. `ws-verify` was not invoked separately.

`ws-shared/review/documentation.md`'s time-relative claim detector. The risk list did its job.

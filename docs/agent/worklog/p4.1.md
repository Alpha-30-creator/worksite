## p4.1 — Write the README · 2026-11-02 · @Alpha-30-creator

**What changed:** `README.md` rewritten, 193 lines. The problem in three paragraphs, then what it
is, four opinions, the thirteen skills, what you need, what works and what does not, where to read
next. Head of the critical path to a tag — p4.2's `INSTALL.md` and p3.4's docs index are written
around it.

**Decisions:**
- **Rewrite, not edit.** The old README predated the pack being in the repo and said so in three
  places, all false of the tree. It had become this project's own top documented risk: a doc
  asserting a capability the pack does not have, written from the plan rather than from the tree.
- *Rejected:* **a quickstart block.** The obvious README move and the clearest way to fail — there
  is no install path until p4.2, and the npm line installs agent-sync rather than worksite. A
  quickstart that does not work is worse than admitting the project is not installable. No badge,
  no install command; the one allowed npm-scope exception went unused as a result.
- **The thirteen "Ends with" cells are lifted from each skill's own `description:` frontmatter**
  rather than written fresh, so the table cannot drift from the skills. p8.1 rewrote all thirteen
  for exactly that property.
- *Rejected:* **the loop table.** It was byte-identical to the concepts page's, and its five
  terminal states appeared a third time in this file's own skills table. A hand-off that sends a
  reader somewhere to meet the same table again is padding rather than a pointer. Replaced with one
  own-words paragraph; each terminal state now appears exactly once here.
- *Rejected:* re-arguing the opinions at the concepts page's length, and the standalone
  four-design-moves section. Folded into the four opinion paragraphs; a mechanism is no use to a
  reader who does not yet want the opinions.
- *Rejected:* restating the claim asymmetry in the dependency table as well as in the guide bullet.
  One sentence true in every case, with the full asymmetry one click away, is the same discipline
  that deleted the loop table.
- **The claims audit is the method, and deletion is its teeth.** 40 claims: 37 established directly
  against the tree, 4 corrected, 1 **deleted rather than softened** — a drafted sentence welcoming
  issues, which nothing in the tree establishes. Softening it to "may be welcome" would have made
  the README the source of a policy that does not exist.

**Evidence:** PR #6. `bash scripts/check.sh` green, and again via the hook. All 32 links resolved
from the repo root. Voice and private-path sweeps clean. One row was not establishable from this
repo — the Node `engines` constraint, there being no `package.json` here — and `claims.md` records
how it was established instead rather than leaving it unmarked.

**Risks learned:** one class, in three instances, and it is the mirror image of the risk already on
the list. The existing entry is *a doc asserting a capability the pack does not have*; all three
corrections here were **an absolute asserted where the tree has an asymmetry**:
- "nothing else in the pack depends on `ws-env`" — two skills invoke it, and in one it is the whole
  body of a numbered section. The headline guarantee was true; the absolutes around it were not.
- "the other four trackers" — four adapters exist, so excluding one leaves three, and the same file
  said "four adapters plus `kind: none`" eleven lines later.
- "the claim lock on file trackers" — a task file outside a repo has no lock at all.

The method lesson, worth more than the fixes: **grep the subject of the claim, not a proxy for it**,
and **a number appearing twice in one file is a claim about arithmetic**. The audit tested whether
`ws-env` exists, not whether anything calls it; and it never compared the two counts to each other.
The third instance was caught only by reading three related passages together, which is not what a
per-claim audit does.

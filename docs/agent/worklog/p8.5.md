## p8.5 — ws-fanout cannot isolate work outside the project's repos · 2026-11-02 · @Alpha-30-creator

**What changed:** the cartridge can declare a **shared external store** —
[`shared_stores`](../../integration/cartridge-schema.md) — and `ws-fanout`'s safety gate reasons
from that declaration instead of a skill knowing about any particular store. The gate gained a
second question, a per-store classification where an undeterminable track is **dropped**, and a
fifth shared-resource row for a global publish command. This project now declares the agent-sync
library, and the `worktrees: true` open question stopped being a remembered rule and became a
declared key. Shipped in a two-track fanout batch with p4.3, which merged first by design.

**Decisions:** recorded in full in
[ADR 0003](../../decisions/0003-shared-external-stores-are-declared-in-the-cartridge.md), which
keeps the five rejected alternatives. The short form:
- **A top-level list, not an entry under `repos:`.** Decisive argument: `ws-plan`, `ws-start` and
  `ws-verify` all loop over `repos:` and would fetch, branch, worktree and verify a store as if it
  were project code — inverting the key's only meaning. Rejected too: a boolean `shared_library:`;
  `ws-fanout` holding the library path itself; carrying it in `machine:`, which has no merge
  semantics and no reader (p8.21); and an `isolated_by_worktrees:` field, which could only ever
  hold `false` and would invite trusting the author on the one fact the gate derives itself.
- **Two acceptance criteria were reworded before any code, and the user approved the rewording.**
  "When a track edits anything outside `repos:`" is unimplementable as observation, because the
  gate runs before any work exists; it became declare-then-detect. "At most one such track per
  batch" is implemented **per store**, a strict superset — identical here, and it refuses less
  where refusing would be false.
- **`unknown` is a drop, not a pass**, following the house pattern the `UNREADABLE` branch already
  set: a gate that cannot find its input must not silently choose the unsafe answer. Two scopes of
  stop kept distinct — an unreadable cartridge stops the whole batch, an undeterminable track drops
  that track.
- **One reader, one writer, one definition site**, stated in the schema page and the ADR, because a
  key nothing reads is p8.21's defect and this change must not repeat it one phase later.
- **`ws-start` was deliberately left alone**, though it is the skill that claims every
  single-session track and its `task.md` shape has no `- Stores:` line. Adding one would shift its
  four citations on the schema page, which is the exact defect this track's review had just found
  in this track. Filed as p8.27 instead.
- **A review Must fix was overturned by the lead**, with the reasoning kept: the cartridge's new
  CI bullet was false when written and true at merge, because p4.3 merged first. The alternative —
  restoring "CI does not exist yet" — leaves a bullet false in the other direction with nobody
  owning it, which is the defect p8.25 exists for. Converted into a ship gate, which passed.
- Rejected at ship-time by the builder, correctly: running `agent-sync save` or `publish.sh` itself.
  Both push, and `ws-fanout` forbids a subagent pushing — so the library edits were handed to the
  lead undeployed. That the two skills disagree in writing is now p8.30.

**Evidence:** [PR #9](https://github.com/Alpha-30-creator/worksite/pull/9), merged as `020a085`,
published as `3681a1b`. `bash scripts/check.sh` exit 0 throughout; §4 went from three differences to
`ok — identical` once the publish ran. The gate's **degrade** was proved rather than asserted: with
no `shared_stores:` key, and with the template's `shared_stores: []`, it prints
`read, and no store declared` and proceeds — behaviour identical to before the change, under bash
and zsh both, since the iteration uses `while IFS= read -r` rather than `for … in $var`.
`ws-refine`'s graph audit is clean on the library **and** on the deployed copies, and the new gate
is present in all three agents' `ws-fanout` — p8.9's lesson applied rather than trusting a
library-only pass. **Not proved:** that the gate fires correctly on the next real batch. That is a
claim about an agent's behaviour, and only a later real `ws-fanout` run can settle it.

**Risks learned:** one line added to [`risks/common.md`](../risks/common.md) — a paragraph written
to manage citation drift that is itself incomplete reads exactly like a complete one. This track's
deferral paragraph named three files and omitted `ws-setup`, the file the change edited most
invasively, with sixteen citations on the page. Found by review, not by the builder's own
re-derivation pass.

## p8.17 — `docs_home` doubles in four sites, and `ws-fanout` silently takes the unsafe branch · 2026-11-02 · @Alpha-30-creator

**What changed:** four `<docs_home>` path sites corrected in the library, `ws-fanout`'s isolation
gate rewritten to name three outcomes with "unreadable" as a stop, one clause added to
`ws-shared/tracks.md`'s isolation bullet, a `ws-setup` node added to `ws-fanout`'s What next?, and
six edits to the cartridge schema page resolving gap 13. Deployed to all three agents and published.

**Decisions:**
- **The dominant form was never in question, and the count was never the argument.** 31 of 35 sites
  read `docs_home` as the agent directory; four appended `/agent`. But `ws-setup`'s own template
  writes `docs_home: <project>-docs/agent`, so the **definition** of the key settles it.
  `stacks/hexagonal-nest.md` corroborates from the other side, reading `<docs_home>/../engineering/`,
  which only resolves if `docs_home` sits below the docs root. *Rejected:* flipping the other 31
  sites — minority rule across 16 files, invalidating every cartridge value including the template's.
- **Readability is tested before content**, so "read it, no key" is distinguishable from "could not
  read it". *Rejected:* treating unreadable as `worktrees: true` — the worse default, N agents
  sharing a tree while being told they are isolated.
- **The stop refuses two specific alternatives by name**, because forbidding in general is not
  enough. The *different repos* hatch is refused **unconditionally** after review — its precondition
  is the cartridge's `repos:` list, but an agent can see repos on disk and the skill elsewhere tells
  it to infer them from the task, so a ban resting on a defeasible fact is weaker than it needs to
  be. And searching for the cartridge elsewhere is refused by name, being the likeliest wrong fix a
  future reader proposes.
- **AC2 shipped unflagged.** A project with no readable cartridge that previously got the `false`
  branch now gets a stop. R5 says new behaviour arrives behind a flag defaulting to today's —
  *rejected* here, because today's behaviour **is** the defect and flagging it would preserve the
  bug. R1 still holds: a readable cartridge with no `worktrees:` key behaves exactly as before.
- **Gap 13 updated, not closed**, since the page cites gaps by number from its own body. The
  corrected figures are recorded alongside the wrong ones, explicitly labelled, so the error does
  not propagate silently.
- *Rejected:* fixing the three other gates with the same shape. One follow-up task, three sub-items.

**Evidence:** PR #7, plus library merge `c5960de`, `agent-sync save` deploying to claude, codex and
cursor, and publish commit `f7f1f64` carrying the change into this repo's `skills/`. Gate verified on
five fixtures — key present, key absent, file missing, file present but **mode `000`** (which a bare
`[ -f ]` waves through, which is why the test is `-r`), and a path containing a space. The decisive
demonstration: against this project's own cartridge the **old** form exits 2 with empty stdout while
the **new** form returns `worktrees: true` — an isolated project read as not-`true` on every run.
Graph audit clean, and re-run against the live library after deploy. **Not proven, and stated rather
than implied: that an agent obeys the stop.** The deliverable is wording; the claim is only that the
unsafe branch is unreachable by reading the table, and the review tried four routes back onto it
without success.

**Risks learned:** two, both about checks rather than about this fix.
- **A check whose silence reads as a pass.** This is the defect's own class, and the graph audit this
  task was required to run has it twice: its `cd` into the library can fail silently, leaving every
  loop to run zero times and report a clean audit of a change it never saw; and its coverage is
  **forward only** — it verifies that every skill *named* in a What next? exists, with no reverse
  check that every exit the prose *offers* is listed. So this task's own new exit left the audit
  clean. Belongs in `ws-shared/review/tier1-universal.md` as a universal: where a check greps, parses
  or queries for a condition, establish that the input was **read** before branching on what it said.
- **An insertion makes citations two lines below it stale.** Citation drift bit twice inside one
  track: nine citations re-resolved in round one, six in round two — three of them pre-existing and
  untouched, made wrong by a two-line insertion above them. That is the shape that survives review,
  because nobody diffs a line number nobody edited.

**Also:** the quoting defect was introduced by this fix rather than inherited. The old line passed
the path as a `grep` argument, where a space merely globbed wrong; the new assignment form turned the
same input into a hard parse failure — reporting UNREADABLE with an **empty** path, which also
emptied the one variable the stop's "say the path you tried" depends on. It failed safe, but it made
a soft failure sharp while making the branch safe.

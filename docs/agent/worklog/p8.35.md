## p8.35 — `ws-env` and `ws-sync` each give a confidently wrong answer and exit clean · 2026-11-02 · @Alpha-30-creator

**What changed:** four library files. `ws_root()` in `ws-env`, `ws-sync` and
`ws-shared/reference.md` reads a named `$proj` instead of `$1`, with the reason at the definition;
both real call sites and the reference snippet set it first. `ws-sync`'s repo sweep now considers
the workspace root alongside its children, counts what it examined, and prints `NO REPO FOUND` when
it examined nothing. `ws-refine` gained `part 3b` — no `$1`–`$9` or `${1..9}` in a skill body — and
a prose rule on verifying a change to a skill's own text in two runs. **No repo file changed**;
the pack reached the repo through `publish.sh` (`cbcc499`), so there is no PR, per ADR 0002.

**Decisions:**
- **Rejected escaping `$1`.** It would rest on undocumented harness behaviour, and a wrong guess
  fails exactly as silently as the bug.
- **Rejected inlining the `sed` at each call site** and deleting the helper. It works — each file
  calls it once — but it abandons the helper idiom `reference.md` documents and `ws-sync`'s own
  `projects()` follows, leaving two styles where the whole point was one.
- **Rejected a new dated record**, which this task's own plan called for. p7.1's record already
  carries the measurement, and the durable *rule* went into `ws-refine`'s prose, where an agent
  meets it at the moment it matters. The reviewer agreed and found the one gap — the prose stated
  the platform fact without saying where it was measured — which is now a pointer.
- **Rejected `$0` in `part 3b`'s pattern.** Fenced awk programs use `$0` as a field reference, so
  including it false-positives on the audit's own code. `$@`, `$*` and `${10}`+ are untested
  against delivery, and the part's heading names what it covers rather than implying more.

**Evidence:** `verify/A1` the pre-deploy delivery test, which **reproduced the defect** on the exact
argument string and so established the test was sensitive; `A2` the sweep against fixtures in paths
containing spaces, fixed versus old, where the old form is silent on both; `A4` the post-deploy
state. `check.sh` exit 0 throughout; leak scan clean on all four files; deployed to claude, codex
and cursor with 0 positional parameters remaining in the executable lines of either skill.

**Not closed by observation, and stated as such:** the confirming *delivery* read could not be taken
after the deploy — the harness served a cached copy of a skill already loaded this session
("instructions unchanged"). What is proved instead is stronger in one respect and weaker in another:
the pre-deploy capture shows `$HOME` surviving the same line in which `$1` was replaced, so named
variables are not substituted and positional ones are; the fix removes every positional parameter,
so nothing remains for delivery to alter. But nobody has read the fixed text as delivered.

**Risks learned — the fourth instance of p8.24's class, and two more at one remove:**
1. **`part 3b` counted into `npos` and my comment claimed `npos` reached the verdict. It did not.**
   A clean line could have come from a part that scanned nothing — p8.24's defect, in p8.24's audit,
   one part later, with a false comment making it worse than silence. Caught by re-reading the new
   part against p8.24's own rule while writing the reviewer's brief. Fixed with a zero-assertion
   **and** a cross-check against part 3's independent denominator, so part 3b cannot agree with
   itself about having read the pack. No fixture could have caught it: every fixture fed it a
   readable library.
2. **`reference.md`'s call site was left passing an argument** to a helper that no longer takes one.
   That file was edited *only* so one correct idiom would exist to copy; half the edit made the
   documented snippet reproduce the original bug, with nothing to catch it — part 3b scans
   `SKILL.md` only and there was no `$1` left to grep for. Found by the review.
3. **A recorded diff was stale**, generated before the `npos` fix, so the artifact meant to evidence
   the fix asserted the defect instead. Found by the review comparing the artifact to the live file
   rather than trusting it.

Items 2 and 3 are the class at one remove: not a check that passes without running, but **an
artifact that reads as evidence of something it predates.**

**Also learned:** `part 3b`'s fence anchor was column-0 only and the pack has indented fences
(`ws-task` has one inside a numbered step), so a `$1` added there would have passed the gate. Fence
counts were verified balanced across all fourteen skills before widening the anchor, since an odd
count would invert the scanner's state for the rest of a file.

`ws-shared/reference.md`, `ws-refine/SKILL.md`.

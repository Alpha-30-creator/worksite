## p7.3 — Nothing runs the README claim checker, so a claim can go stale between tags · 2026-11-03 · @Alpha-30-creator

**What changed:** `scripts/check-readme-claims.sh` is now **section 7 of `scripts/check.sh`** —
called, not inlined, with no gate of its own, so there is still one command and one exit status.
Before this, p7.2's checker enumerated every checkable README claim and **nothing executed it**:
`verify` is `check.sh` and deliberately the only gate (AGENTS.md), so the checker was a rule with
no path that ran it, on the repo's front page, one day after a release whose single criterion was
that those claims held. The section states what it read per ADR 0004, distinguishes "this claim is
false" from "a tool this machine lacks means I did not look", and refuses a checker that runs and
certifies nothing. The section count was corrected in six places, three of which the first draft
missed.

**Decisions:**
- **Called rather than inlined.** The claim-reading is long; inside the gate it would make the
  gate unreadable, and the two files have different jobs. *Rejected:* inlining it, and
  *rejected:* a second `verify` command, which AGENTS.md forbids and the criterion rules out.
- **An `UNCHECKED` disposition, distinct from both `ok` and `FAIL`.** The Node floor is read out
  of `agent-sync`'s own `engines` field, so it is uncheckable where `agent-sync` is absent —
  which is CI and every reader, where it had been a hard failure. *Rejected:* leaving it a
  failure, measured to turn CI red on a README that holds. The line drawn: only a missing **tool**
  qualifies; "no claim of that shape in `README.md`" stays a failure, because that means the
  README moved out from under the check. *Rejected:* exit code 2 for "passed with unchecked
  claims" — every existing caller uses `&&` or `if`, so a third code reads as failure at a tag.
- **The checker self-reports its totals** in one `-- counts --` line, incremented by the very
  functions that print each claim, and `check.sh` reads all five fields. *Rejected:* a numeric
  floor ("at least 10 groups, 30 oks") in `check.sh` — that puts expected numbers in the gate,
  which is the DIRECTION defect the checker's own header forbids.
- **Group 8 tests membership against the shared open set** and keeps its own arms for wording
  only. *Rejected:* rewording the comments to admit group 8 enumerated its own set; the invariant
  is worth having rather than documenting its absence.
- **Both interpreters are probed by using them**, not by `command -v`. *Rejected:* presence
  checks, twice over — see below.
- **Claim coverage was deliberately not widened.** The README states the thirteen four times and
  two of those are read, so a stale figure at `README.md`:48 or :49 passes. That is claim
  coverage, p7.2's subject; this task is the wiring. Recorded as a limitation.

**Evidence:** [PR #23](https://github.com/Alpha-30-creator/worksite/pull/23), merged `bcebaec`.
Eight artefacts in the track's `verify/`: the gate in every run site, the `--staged` question
across seven cases, 13 paraphrase rows with 3 notes, every section-count statement with every
cited line number re-derived from the files, **15 mutations and 15 refusals** plus a negative
control where the checker certifies nothing, the five `UNCHECKED` branches, and every
reproduction from both review rounds re-run against the shipped code. CI green:
`10 claim group(s), 38 claim(s) hold, 1 not checked` — the one being the Node floor, named.

**Risks learned — every stage found its defect in the fix, not the original:**
- **Round one:** the counts were re-derived by grepping the checker's output, so reverting the
  checker's heading format — a line *this change itself introduced* — made section 7 report
  `0 claim group(s)` **and call it ok**. `--staged` asked `git diff --name-only`, which names
  neither a staged deletion whose file is still on disk, nor an untracked file the checker reads,
  nor a non-git tree, and prints a conflicted path twice.
- **Round two:** having moved to a self-report *precisely* to stop inferring state, I read four of
  its five fields and left `fail=` unread — so the gate's only evidence of a failed claim was
  still the exit status. And `command -v python3` succeeds for a python3 that cannot run (macOS
  with no Command Line Tools), which took the present branch into a `package.json` walk that
  **never terminated**: `dirname ""` is `.`, `dirname "."` is `.`. That loop predates this task
  and was harmless while nothing ran the script; section 7 is what would have put it in `verify`,
  the pre-commit hook and all three publish sites, hanging every one with no output.
- **CI found a ninth defect neither review round could.** `mktemp -t wsclaims` is BSD-only — GNU
  mktemp refuses a bare prefix — so the paraphrase check died on every Linux while passing here.
  The pack's own documented cross-platform trap, committed by its author, caught by the one
  environment this is not developed in. The general form: **a review that runs where the author
  runs cannot find a platform defect, however adversarial it is.**
- **Two of the checker's ten groups were only ever correct on an idle board.** They counted `[ ]`
  alone as open, so *claiming any task* failed the gate. A check written as evidence for one task
  is written against the tree as it stood that day, and the states it never saw are the ones it
  gets wrong the moment something runs it on every commit.
- **`[?]` blocked on a decision is a sixth roadmap marker**, defined in
  `ws-shared/trackers/roadmap-files.md`, `docs/roadmap/README.md` and
  `docs/integration/cartridge-schema.md`. My comment asserted five and said "only `[x]` and `[-]`
  are closed", so marking any task blocked would have refused every commit. Enumerated from
  memory in a repo that writes it down three times.
- **Three findings were false statements written while fixing false statements**, now the seventh
  through ninth on this project. The worst asserted an invariant the code did not have —
  "the open set is defined once and shared by groups 8 and 9" — in four places including a commit
  message, disproved by narrowing the one definition and watching one group move.
- **A partial re-derivation feels complete.** This task's own comment block moved
  `publish.sh`:312 and :356 to :316 and :360. I re-derived the two citations *above* the
  insertion, found them unchanged, and stopped. Third citation drift in two days, in
  `SECURITY.md`, which warns about citation drift.
- **A comment taught a mechanism nobody could reproduce.** It blamed heredocs inside command
  substitution on bash 3.2; a reviewer failed to reproduce that across five shapes and I failed
  across two more, and the pre-fix version parses clean. The cause is still unknown and the
  comment now says so instead of inventing one.
- **Every figure in this repo was measured under a `grep` CI does not have.** Unqualified `grep`
  here is `ugrep 7.8.4`, not `/usr/bin/grep` (BSD grep 2.6.0-FreeBSD); CI runs GNU grep. Only a
  small common subset is used and CI is green, so nothing is known to differ — but the artefacts
  in `records/` and `verify/` were all produced under the first of three implementations.

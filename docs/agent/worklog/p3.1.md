## p3.1 — Write the cartridge schema · 2026-11-01 · @Alpha-30-creator

**What changed:** `docs/integration/cartridge-schema.md`, 780 lines — every cartridge key with its
type, whether it is load-bearing, its default, which skills read it, and what happens when it is
missing. Sections by concern, each ending in a six-column key table. 45 keys: 33 read by name, 9 by
concept only, 2 written and never read, 1 read but never specified. First reference doc in the repo.

**Decisions:**
- **Sections by concern, not one flat table.** A flat table cannot carry `repos:` (a list of maps) or
  `tracker.*` (four disjoint key sets conditional on `kind`); it would either lie about
  required-ness or grow a "when" column that becomes prose anyway.
- **Document the schema as it is, with gaps named** — 14 of them. *Rejected:* specifying the missing
  keys as though they existed, which would make the page wrong about the system and would silently
  turn a documentation task into a `ws-refine` change to `ws-setup`.
- **A provenance mark on every degrade cell and every default** — *stated* with a citation, or
  *inferred*. The pack documents degrade behaviour nowhere per key, so the alternative was presenting
  inference as fact. Extending the mark to the `default` column came out of a blind test that caught
  the column conflating "the default a reader applies" with "the value the template ships" — a real
  false-capability claim, self-contradicting on `worktrees`.
- **`merge_style` documented as a real key with no definition**, type and placement both *inferred*.
  A skill reads it, nothing writes it, so every project is in the missing case and the fallback is
  the key's only behaviour. *Rejected:* inventing a value set, and omitting it.
- **`docs_home` stated in its dominant form, unhedged.** 27 sites across 13 skills treat it as ending
  `/agent`; 4 do not. *Rejected:* hedging into "either form works" — 27-against-4 is not a toss-up,
  and a schema page that hedges on where the cartridge lives is useless.
- **The stack tag set reproduced on the page**, dated. Without it a reader with only this page cannot
  write `stack:` at all — the value set lived in a file the page merely linked to.
- **Criterion 4 re-scoped to "met to the limit of what the pack can express".** *Rejected:* both
  alternatives — leaving it open pending a pack change (parks a finished document behind someone
  else's bug) and ticking it unconditionally (untrue). 17 page-side blocks found and fixed; 7
  pack-side residue items filed instead.
- *Rejected:* re-planning when the track resumed — the plan was approved before p8.10 and discarding
  it would have thrown away a passed gate. *Rejected:* a third blind pass; the remaining gaps are
  pack-level and another reader would only re-find them.
- *Rejected, against the lead's instruction:* downgrading the device-id sentence to *inferred*. The
  claim exists verbatim at `ws-shared/new-device.md`:120-121 — the citation was mis-filed, not
  fabricated, and the lead's grep had been scoped to one file. Marking a claim *inferred* when its
  source can be quoted hides a real citation behind the honesty convention.

**Evidence:** PR #1. `bash scripts/check.sh` green on all four sections. The "read by" column comes
from an exhaustive grep ledger (`verify/key-ledger.tsv`), three passes per key, `examples/` and
`templates/` excluded as data rather than readers; every `file:line` on the page was resolved and its
target line read, with zero blank targets. Three citation errors originated in the ledger itself and
were transcribed faithfully onto the page, so the whole ledger was re-resolved rather than the five
reported lines. Criterion 4 was tested by two blind readers with access to the page and nothing else:
round one raised 14 gaps (9 page defects, all fixed), round two raised 5 more (all page defects, all
fixed) and confirmed the first round's fixes held. Two independent review rounds, 4 must-fix and 5
should-fix, all addressed. `ws-verify` was not invoked separately — verification was produced inside
the build as evidence per criterion.

**Risks learned:** one class, not yet filed — a doc citing `skills/` by `file:line` drifts the moment
a skill gains a line, and `check.sh` resolves links but never line numbers, so a wrong citation reads
exactly like a right one. It belongs in `risks/common.md`, which track p6.1 holds in this batch;
adding it now would collide, so it goes in after p6.1 merges.

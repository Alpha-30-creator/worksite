## p6.1 — Build publishing into ws-refine · 2026-11-01 · @Alpha-30-creator

**What changed:** `scripts/publish.sh` (new, executable) copies the generic `ws-*` skills out of the
agent-sync library into this repo behind the leak guard, and a mandatory `## Publish` step in
`ws-refine` invokes it. Plus ADR 0002, a rewrite of `sync-direction.md` (which promised a mechanism
that did not exist), and two risk lines. **There was no publish mechanism before this** — parity was
hand-copying, and `check.sh` §4 already said in its own comment that the hard gate belonged here.

**Decisions:**
- **The script lives in the target repo, not the library.** The guard and its pattern file are here,
  `check.sh` is git-aware so it cannot be pointed at a loose directory, and nothing new enters the
  library — only `SKILL.md` changes, which removes the untestable question of whether
  `agent-sync save` preserves an executable inside a skill directory.
- **Targets resolve from `~/.agent-sync/publish.targets`, which is never published.** Required,
  because the target's own path matches `leak-patterns.txt` — a hardcoded path in a published skill
  would be caught by the guard it runs.
- *Rejected:* **any git-level mirror or subtree.** The library's history carries 59 private skill
  packs (73 directories, 14 of them `ws-*`), so sharing history is a hard no. The most important
  rejection here.
- *Rejected:* inline bash in `SKILL.md` — a gate must be an exit code, not prose an agent can
  "adapt"; a script shipped in the library — it would have to guess the target's guard; folding it
  into `agent-sync save` — different product, runs for every project; symlinking `skills/`; CI
  pulling from the private library.
- **Scope is the glob `skills/ws-*`, never a hand-maintained list**, because bookkeeping rots. ADR
  0002 says plainly that this holds **by the library's naming convention, which review must keep
  true** — not "by construction": a future private pack named `ws-anything` would be copied.
- **Publish commits land directly on `main`**, against the cartridge's `pr_into: integration_branch`.
  Carved out deliberately and recorded: `integration_branch` *is* `main` here, so the rule was
  written for projects with a staging branch this repo does not have; a publish is a plain copy of
  content already reviewed in the library; the guard runs three times plus the hook. Residual risk
  stated rather than argued away — `main` is public and permanent, and a bad publish cannot be
  reverted away because the objects remain.
- **Reference data files inside skill directories are allowed and listed on every run.** A literal
  Markdown-only rule refuses every real publish, because the pack ships
  `ws-shared/examples/manifest.tsv` and `device.yaml`. *This deviated from the lead's instruction and
  was flagged rather than taken silently.* The listing is the compensating control, since a secret
  can wear any extension. A strict rule needs those two files moved out of `ws-shared/` first.
- **Criterion 5 was already met by p2.1** and was not claimed as new work — only a pointer sentence
  was added to the existing "edit the library, never a deployed copy" clause.

**Evidence:** PR #3, plus a separate merge in the private library (`0e3ddcf`). Every refusal path
proven by execution against throwaway fixtures under a path containing a space, run under `bash` not
zsh; suites re-runnable in the track's `verify/`. Independent review found **four must-fix**, all
fixed and re-proved by execution: a refusal after the real tree was written left the repo *staged*
while printing "Nothing was published" (now restores to a pre-captured HEAD and verifies it); the
committed bytes were never scanned, with the script delegating that to a hook it never checked was
wired (now a `hooksPath` preflight refusal plus a `check.sh --staged` re-run on the real staged
tree); a symlink inside a skill published an absolute filesystem path the guard never read, because
`check.sh` reads content with `cat`, which dereferences; and the glob copied whole trees with no file
filter, so a seeded `.env.local` containing a secret committed at exit 0 with the guard green.
**The mechanism then published itself for real at ship time** — candidate scan, staged-tree scan,
pre-commit hook, commit `0e6481a`, real push — and `check.sh` §4 went from reporting drift back to
"ok — identical". Criterion 1's behavioural half is now partly earned: the command is proven end to
end including the push; that an agent performs it unprompted on the next refinement is still to be
observed.

**Risks learned:**
- Added to `risks/common.md`: a doc citing `skills/` by `file:line` drifts the moment a skill gains a
  line, and `check.sh` resolves links but never line numbers, so a wrong citation reads exactly like
  a right one. Found on p3.1, held until this track merged because it owns that file.
- **Found while retiring this track, not yet filed:** the retirement guard in `ws-shared/tracks.md`
  refuses a worktree whose branch has **no upstream**, on the stated grounds that its commits exist
  nowhere else. This track's library branch was merged locally into `main` and pushed via `main`, so
  it has no upstream of its own while both its commits are reachable from `origin/main`. The guard
  tests a proxy rather than the property it cares about, and so refuses safe work — the operator's
  only escape is to override a safety check, which is how a check becomes routinely bypassed. The
  correct test is reachability from any remote-tracking ref.
